# Architecture and Implementation Decisions

## D1 — Python 3.11 + FastAPI backend
FastAPI chosen for async support, automatic OpenAPI docs, and Pydantic v2 integration. SQLAlchemy 2.0 ORM used for type-safe database access. Alembic handles schema migrations.

## D2 — PostgreSQL as primary database
Relational model suits the structured time-series and metadata. Indexed on (source_id, observed_at) for all observation tables. INSERT ON CONFLICT DO NOTHING ensures idempotent pipeline reruns.

## D3 — SQLite for test suite
Tests use an in-memory SQLite database via conftest.py engine override. Avoids PostgreSQL dependency in CI while testing all ORM models and API routes.

## D4 — Chronological 70/15/15 train/val/test split
Time-series data must not be randomly shuffled. The split is strictly chronological: first 70% for training, next 15% for validation/tuning, final 15% as held-out test. This prevents temporal data leakage.

## D5 — Lag and rolling features use shift(1)
All rolling statistics use `shift(1)` before computing the window — the current observation is excluded. Lag=1 at position i uses value at position i−1. This is verified by `test_rolling_excludes_current_row` and `test_lag_1_equals_previous_row`.

## D6 — MAPE gated by zero-threshold
MAPE returns None when >10% of actual values are at or below 0.1 kWh. Solar generation has many night-time zero values; MAPE is undefined/misleading in that context.

## D7 — Anomaly alerts are advisory only
The explanation text always says "investigation recommended" — never "fault confirmed." This is enforced in both backend alert generation and frontend display.

## D8 — Demand module is conditional
The demand forecasting and energy-balance gap analysis only activates when a compatible demand dataset is available. The platform does not invent or interpolate demand data. CEA national data is not compatible at hourly site-level resolution.

## D9 — Open-Meteo as primary weather source
Free, no API key, CC BY 4.0, global coverage, hourly resolution, UTC timezone, includes all required solar radiation variables. NREL NSRDB is the preferred alternative for production use (requires free API key).

## D10 — Synthetic sample data labelling
Sample data in `data/samples/` is generated by `scripts/generate_sample_data.py` and explicitly labelled SYNTHETIC in all outputs, UI notes, and documentation. Must not appear in academic results sections.

## D11 — React + Vite frontend
React 19 with Vite for fast HMR. TanStack Query for server state and caching (30s staleTime). React Router v7 for navigation. Plotly.js for all analytical charts with a consistent dark theme.

## D12 — No authentication in v1
Authentication is deferred — the platform runs locally for academic demonstration. Security note added to README. If deployed, add FastAPI OAuth2 + bcrypt password hashing before exposure.
